# Паспорт носія у рівняннях Eq.4/5/6: резолвер, результат, план подальших кроків

Дата: 2026-09-20. Статус: **реалізовано (варіант A, адитивно)**, план решти — розділ 6.

## 1. Навіщо

Питання кафедри на попередньому звіті: як ураховано тип автомобіля, підвіску, шини,
завантаження. Стан до цієї роботи: паспорт носія (`# vehicle_*`, контракт v3) записувався
і був ключем калібрування, але у рівняння не підставлявся — конвеєр завжди брав Eq.6 з
номіналами (`IRI_MULTI_DEFAULT_PARAMS`, усі 1.0). Модель при цьому має сім членів
(Grms, швидкість, Npeop, Stif, DampF, TyreS, const) і три набори за класом носія
(Eq.4 LEV, Eq.5 DSD, Eq.6 GENERIC) — `metrics/iri.py`.

## 2. Рішення

Паспорт → **резолвер** → набір Eq.4/5/6 + чотири параметри → **додаткова** колонка.
Опублікований `iri_multi` (Eq.6, номінали) **не змінюється**: усі числа розділу 4
дисертації, поданої статті та калібрувальні набори веб-адмінки лишаються чинними.

| Поле паспорта | Вхід | Відображення | Походження |
|---|---|---|---|
| `vehicle_type` | набір | `van`→Eq.4; `sedan`→Eq.5; решта→Eq.6 | `book` / `default` |
| `vehicle_load` | Npeop | driver_only 1; two_people 2; half_load 3; full_load 4 | `book` для людей, `assumption` для вантажу |
| `vehicle_suspension_type` | Stif | leaf_spring 1.2; independent, torsion_beam 1.0; air 0.8 | `assumption` |
| `vehicle_suspension_condition` | DampF | new, good 1.0; worn 0.8 | `assumption` |
| `vehicle_tire_size` | TyreS | диск ≥16″ 1.0; 15″ 0.9; ≤14″ 0.7 | `assumption` (найслабше) |
| `vehicle_mount_rigid` | — | `false` → попередження | не член рівняння |
| відсутнє / невідомий токен | — | номінал, Eq.6 | `default` + попередження |

Довідник задає лише діапазони (Npeop 1–4 по 70 кг; Stif, DampF ±20 %; TyreS 0.7–1.0)
без таблиці «реальне авто → рівень», тому кожне відображення — **задокументоване
припущення методики** (дисертація, таблиця 2.2а), а не факт довідника. Таблиці
закріплені літерально в тестах: підганяти їх під дані заборонено.

## 4. Результат перерахунку (274 пари, той самий еталон)

| Показник | Eq.6 (`iri_multi`) | Eq.4 за паспортом |
|---|---|---|
| ρ Т1016 / М-03 | 0.941 / 0.209 | 0.933 / не визначена (110/110 нулів) |
| Зсув Т1016 / М-03 / пул, м/км | −1.611 / −1.459 / −1.550 | −2.279 / −1.463 / −1.952 |
| LORO MAE М-03 / Т1016 після корекції зсуву | 0.164 / 0.590 | 0.816 / 0.836 |

Механізм: швидкісний член Eq.4 (−0.07 проти −0.06) на 61 км/год = −0.61 м/км; сталі
доданки з параметрами носія 2.99 проти 3.31 = −0.32; більший коефіцієнт при Grms
= +0.19. Разом −0.74 проти спостережених −0.67 (решта — обрізання `max(0, ·)`).

**Висновок.** Книжковий клас носія зсув не пояснює, а збільшує; зсув є властивістю пари
«телефон — автомобіль». Числове підтвердження прогалини про непереносність книжкових
коефіцієнтів і аргумент за польове калібрування з провенансом (Phase 3).

## 6. План подальших кроків (пріоритет ↓)

1. **Веб-адмінка: показати нову колонку.** Сторінка запуску і тултип карти — обидві
   оцінки поруч (`iri_multi`, `iri_multi_vehicle`, токен рівняння); у порівнянні
   двох запусків — окремий `delta_iri_multi_vehicle`. Backend читає CSV як є, зміни
   лише у `runs.py`/`files.py` і фронті. Обсяг: пів дня.
2. **Калібрувальні набори з прив'язкою до рівняння.** Набори Phase 3 підігнані під
   `iri_multi` (Eq.6). Додати до ключа набору токен рівняння (`eq6` за замовчуванням)
   і заборонити застосування набору Eq.6 до колонки Eq.4 — інакше провенанс
   «протікає» між наборами. Обсяг: 1 день, міграція БД адитивна.
3. **`iri_multi_vehicle_raw` без обрізання нулем** (за аналогією з `iri_psd_raw`) —
   діагностика для рівних доріг, де Eq.4 вироджується у сталу. Обсяг: 1 година.
4. **Тиск у шинах.** Поле `vehicle_tire_pressure_bar` у контракті вже необов'язково
   записується; у рівняннях довідника члена тиску **немає**. Не вигадувати коефіцієнт:
   лишити як контекст і як частину ключа калібрування, поки кампанія не дасть даних
   для емпіричної оцінки (два тиски на одному носієві, ті самі ділянки).
5. **Багатоносійна кампанія** (Walking Profiler G3 + лазерний профілометр): ≥2 типи
   автомобіля, ≥4–5 доріг змішаних категорій, 3 проїзди × 3 швидкості. Критерій для
   таблиці відображення: чи зменшує набір класу зсув на **іншому** носієві того самого
   класу. Якщо ні — таблиця лишається припущенням, а калібрування — індивідуальним.
6. **Перегляд рівнів 0.8/1.0/1.2** лише після кампанії і лише за наявності ≥2 носіїв
   одного класу; до того — без змін (тести-пломби).

## 7. Що не робити

- Не замінювати `iri_multi` резолвленим набором (варіант B) — зрушує всі опубліковані
  числа і калібрувальні набори.
- Не підбирати таблицю відображення під дані валідації — це саме те «винайдення
  калібрування», від якого розділ 2 застерігає.
- Не заявляти «встановлено вплив підвіски / типу авто»: один носій. Коректно —
  «паспорт носія враховано у моделі; перенесення книжкового класу перевірено і не
  підтверджено».
